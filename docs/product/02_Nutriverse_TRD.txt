2. Technical Requirements Document (TRD)

Nutriverse Web Application • MVP Specification

Prepared from the supplied Nutriverse Venture Pitch & Problem Statement, Scientific Problem Research Summary, and Nutrition-First Retail Business Concept.

1. Recommended Architecture

Use a modular full-stack web architecture: React/Next.js frontend, Python FastAPI backend, PostgreSQL database, object storage for product/recipe images, and an AI service behind a backend orchestration layer. The MVP can be deployed as a single web application with clear service boundaries.

6. Nutrition Engine

The supplied concept specifies the Mifflin–St Jeor equation and activity multipliers for individualized calorie estimates. Implement this as a deterministic backend service. Keep the calculation versioned so future nutrition rules can be updated without changing historical records.

7. AI Guardrails

Retrieve relevant food/nutrition records before generating an answer.

Never invent a product's nutrition values.

Return a clear uncertainty message when required data is missing.

Do not diagnose conditions or prescribe treatment.

Use a visible general-guidance disclaimer.

Allow qualified human review in a later phase for condition-specific workflows.

8. Security

Hash passwords with a modern password hashing algorithm

Use HTTPS in production

Validate all inputs

Use authorization middleware

Restrict admin APIs

Rate-limit AI endpoints

Keep secrets in environment variables

Log security-relevant events

Minimize sensitive profile data

9. Performance Targets

Paginate food search

Index barcode and searchable food fields

Cache frequently used catalog data

Avoid sending full nutrition databases to the browser

Lazy-load images and heavy dashboard modules

10. Environment

Use separate development, test, and production configuration. Store DATABASE_URL, AI provider credentials, authentication secrets, and other credentials only in environment/secret management and never commit them to source control.
