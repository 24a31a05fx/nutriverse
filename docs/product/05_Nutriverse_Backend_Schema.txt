5. Backend Database Schema

Nutriverse Web Application • MVP Specification

Prepared from the supplied Nutriverse Venture Pitch & Problem Statement, Scientific Problem Research Summary, and Nutrition-First Retail Business Concept.

1. Schema Principles

Use PostgreSQL with UUID primary keys, timestamps, foreign keys, indexed search fields, and versioned nutrition calculations. Store user profile data separately from catalog data. Keep pack generation records so an order can be traced back to the exact pack composition used at purchase time.

3. Important Constraints

users.email unique.

foods.barcode indexed and unique when present.

nutrition_profiles.user_id unique.

All order items store a snapshot of price/product/pack information so historical orders do not change when catalog data changes.

Use CHECK constraints for non-negative quantities and prices.

Use soft-delete/active flags for catalog records rather than deleting referenced products.

Foreign keys use explicit delete behavior.

5. Calin Pack Generation Data

The pack generator should produce a pack record plus item-level quantities and a rules/calculation version. This allows the application to reproduce what was recommended/selected at that time.

6. Example Entity Relationships

User 1—1 NutritionProfile; User 1—M Orders; User 1—M ProgressLogs; User 1—M ScanEvents; Food 1—1/M NutritionRecords depending on versioning; Recipe M—M Food; CalinPack 1—M PackItems; Order 1—M OrderItems.
